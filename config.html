LLM AI — Configuration

Serveurs LLM (repli par priorité)

Ajoutez un ou plusieurs serveurs Ollama. Chaque LLM a une priorité (1 = la plus haute, essayée en premier) et un drapeau activé. Si un serveur est indisponible, la tâche bascule automatiquement sur le prochain LLM activé selon la priorité.
URL d'accès Emby (ex. http://localhost:8096) — sert à construire les liens d'images retournés au LLM.
Langue des métadonnées et du texte en prose de l'LLM : raisons des recommandations, rapport d'audit, scaffolding des cartes .strm et synopsis TMDB (demandé dans cette langue, repli en-US, traduction LLM en dernier recours). « Auto » = suit la langue d'affichage Emby. Les titres de films/séries, noms de chaînes et champs JSON techniques restent inchangés.

Clés API — services externes

Clés pour les outils d'enrichissement internet. Un champ vide désactive l'outil correspondant (il n'est pas exposé au LLM).
Clé API TMDB pour l'outil tmdb_lookup (enrichissement synopsis/statut). Laisser vide pour désactiver l'outil.
Repli legacy pour la langue TMDB quand « Langue de réponse du LLM » est sur Auto et que la langue d'affichage Emby est illisible. Quand une langue de réponse est choisie, c'est elle qui pilote TMDB (repli en-US, traduction LLM en dernier recours). Ex. fr-FR, en-US.
Clé API TheTVDB.com (v4) pour l'outil tvdb_search (enrichissement séries, synopsis FR en priorité). Repli sur la variable d'environnement TVDB_API_KEY. Vide = désactivé.
Clé ollama.com — sert pour le backend Ollama cloud ET les outils web_search/web_fetch. Repli sur la variable d'environnement OLLAMA_API_KEY. Vide = Ollama cloud désactivé.
Instance SearXNG auto-hébergée (méta-moteur). Si renseigné, l'outil web_search l'utilise en priorité (gratuit, sans quota, résultats JSON). L'outil interroge {url}/search?q=…&format=json — le format JSON doit être activé dans les réglages SearXNG (search.formats). Optionnel : un utilisateur de la communauté n'a pas besoin d'installer SearXNG (repli automatique sur Ollama cloud). Vide = SearXNG désactivé.
Récupère les pages web directement côté plugin (HttpClient) et extrait localement le contenu structuré (titre, métadonnées, JSON-LD schema.org, texte, titres, tableaux) — aucun quota cloud, aucune clé requise. Repli automatique sur Ollama cloud en cas de blocage anti-bot (si une clé est renseignée). Décochez pour utiliser uniquement Ollama cloud (clé requise). Activé par défaut — fonctionne pour tout utilisateur de la communauté.
Clé Google AI Studio pour le backend Gemini (generativelanguage.googleapis.com). Repli sur la variable d'environnement GEMINI_API_KEY. Vide = Gemini désactivé.
Une source par ligne pour l'outil new_releases (alias de l'ancien showbizz_new_releases) : URL seule = flux RSS/Atom auto-détecté ; URL :: @showbizz = extracteur intégré Showbizz.net (blocs « Saison 1 ») ; URL :: regex .NET = extraction personnalisée (groupe « title » requis, « url »/« date » optionnels). Exemple : https://en.wikipedia.org/wiki/Category:2026_Canadian_television_series_debuts :: <li><a href="(?<url>/wiki/[^:"]+)"[^>]*>(?<title>[^<]+)</a>. Vide = outil désactivé. Modifier la liste re-scrappe sans redémarrer (cache 24h clé sur les sources).
Prompt système envoyé au LLM (role: system) à chaque appel.
Quand activé, le journal Emby contient le system prompt complet, le prompt utilisateur, la réponse complète de chaque itération et chaque résultat d'outil. À activer ponctuellement pour comprendre ce que voit le LLM (désactivé par défaut).
Format : « <planification> | <prompt de tâche SÉRIES> ». Planification : Daily HH:MM, Hourly, Weekly <Day> HH:MM, Interval <heures>. La partie après le « | » est le prompt utilisateur du run SÉRIES (étapes 1 + 2 : premieres S01E01 + nouvelles saisons). Exécuté comme un premier run agent indépendant. Déclenchable manuellement dans « Tâches planifiées ».
Prompt du run FILMS (étape 3 : films à venir absents de la biblio, via get_emby_info action=epg_movies). Pas de planification ici — elle vient du champ ci-dessus. Exécuté comme un second run agent indépendant, puis fusionné avec les séries (la page Recommandations affiche deux sections). Vide = pas de run films (séries seulement).
Titres exclus des prochaines exécutions : la tâche les retire de la liste envoyée au LLM (épuration en amont) — ils ne seront plus recommandés. Un titre par ligne. Alimenté aussi par le bouton « Oublier » de la page Recommandations.

À regarder ce soir (recommandation personnalisée par usager)

Section « À regarder ce soir » de la page Recommandations : analyse l'historique de visionnage de l'usager et croise avec l'EPG du soir pour recommander quoi regarder maintenant. Appel à la demande (endpoint plugin), cache par usager.
Option opt-in. Ajoute le genre AI Tonight aux items Emby recommandés (enregistrements non visionnés + bibliothèque) pour les retrouver en filtrant sur ce genre dans n'importe quel client Emby. Une tâche planifiée (Nettoyage genre AI Tonight, 3 h du matin) retire le genre chaque jour ; les runs « ce soir » suivants le réajoutent sur les recos pertinentes. Modifie les métadonnées réelles des items (tableau Genres) — un refresh peut l'effacer (réajouté au prochain run). Indépendant de la bibliothèque .strm (genre AI Suggestion, nettoyage séparé).
Option opt-in, indépendante du genre ci-dessus (les deux peuvent cohabiter). Maintient une collection Emby AI Tonight regroupant les items recommandés (enregistrements non visionnés + bibliothèque) — l'usager la parcourt comme n'importe quelle collection dans n'importe quel client Emby. Non destructive : les items sont référencés (regroupés), jamais copiés ni déplacés ; lire un membre joue le vrai item. La collection agrège des items inter-bibliothèques (enregistrements + films/séries possédés). La tâche planifiée (Nettoyage genre AI Tonight, 3 h du matin) vide aussi la collection chaque jour (coquille conservée, re-remplie au prochain run).
Fenêtre temporelle de l'EPG interrogée (ex. 18:00 → 23:59). Début vide = maintenant ; fin vide = 23:59.
Template du prompt envoyé au LLM. Le profil de goût (historique récent de l'usager) y est injecté à l'exécution.
Max de programmes de la soirée soumis au LLM (après pré-tri par pertinence). Défaut 10.
Durée de validité du cache par usager. 0 = pas de cache (run à chaque ouverture). Défaut 4.
Fenêtre de recherche des enregistrements récents non visionnés (candidats « à regarder ce soir »). Défaut 7.
Si l'EPG + les enregistrements donnent moins de recommandations, complète avec des titres non visionnés de la bibliothèque. Défaut 3.

Auto-programmation & popup au login

Les clients natifs Android / Android TV ne rendent pas les pages plugin HTML : les recommandations ne sont visibles que sur la page web. L'auto-programmation crée les timers Emby des recos à enregistrer → elles ressortent dans le guide EPG natif (badge d'enregistrement) sur tous les clients. Le popup au login signale ce soir ce que l'usager peut regarder (bibliothèque / enregistrements).
Option opt-in (décochée par défaut). Si cochée, après chaque run (tâche planifiée ET login), les recommandations à enregistrer (programmes EPG à venir, non déjà possédées, non déjà programmées, hors drop list) sont programmées en enregistrement (SeriesTimer pour une série, Timer unique pour un film). Aucune programmation tant que décochée. L'utilisateur peut annuler un timer indésirable dans Emby.
Pastille verte + icône étincelle (sans texte, multilingue) en haut à droite de l'image des programmes suggérés par la tâche planifiée — visible dans le guide EPG natif, sur tous les clients. Non destructif : overlay au moment du service, l'artwork stocké n'est jamais modifié (l'enregistrement importé garde l'image d'origine — le badge disparaît une fois l'émission enregistrée) et un refresh EPG est sans effet. Chaque run remplace la sélection badgée ; les diffusions passées s'auto-expirent.
Pastille jaune (sans icône) sur l'image des programmes EPG dont la série ou le film figure déjà dans la bibliothèque — même rapprochement par nom que l'exclusion biblio des outils EPG (Articles FR/EN retirés, casse ignorée). L'usager sait dans le guide qu'il n'a pas intérêt à enregistrer. Même mécanisme non destructif que le badge « AI » (overlay au service, artwork jamais modifié) ; clé de cache distincte. NB : une nouvelle saison d'une série possédée porte aussi le jaune (c'est le même nom de série).
Indépendant de l'auto-programmation : le popup liste ce soir ce que l'usager peut regarder (enregistrements non visionnés, bibliothèque). Toast sur le client qui se connecte (si DisplayMessage supporté) + notification cloche persistante (deep-link) en repli. La cloche reste même si la session ferme avant la fin du run LLM (~30–60 s) ou si le client ne supporte pas le toast.

Bibliothèque .strm des recommandations

Alternative manuelle à l'auto-programmation : après chaque run, le plugin écrit une carte .strm+.nfo+poster par recommandation à enregistrer (programmes EPG à venir, non possédés) dans une bibliothèque Emby dédiée. L'usager parcourt la bibliothèque ; lire une carte crée l'enregistrement puis affiche un clip de confirmation. Créez d'abord dans Emby une bibliothèque de type Films (ou Contenu mixte) pointant vers un dossier vide, puis renseignez son nom exact ici.
Nom exact (sensible à la casse ignorée) de la bibliothèque Emby où écrire les cartes. Indépendant de l'auto-programmation (les deux peuvent cohabiter : le dedup évite les timers en double). Un jeton de sécurité est auto-généré au premier run pour protéger l'endpoint d'activation.

Identification des enregistrements orphelins

Passe quotidienne (04 h) qui repère les enregistrements DVR non identifiés (sans id IMDb/TMDB — souvent des titres québécois absents du catalogue TMDB/TVDB), tente de les résoudre par nettoyage du titre + recherche multilingue (S1), puis par proposition LLM d'un id IMDb validé via TMDB /find (S2), et écrit l'id + métadonnées + affiche en verrouillant le titre EPG (jamais écrasé). Les irrésolus sont marqués pour revue. Opt-in : modifie des enregistrements.
Si cochée, la tâche n'écrit rien : elle logue seulement les orphelins trouvés et la résolution proposée (S1/S2/S3) + un bilan. Sert à valider la qualité des résolutions avant de basculer en application automatique. À garder cochée pour les premiers runs.
Si cochée, après S1/S2 la tâche interroge SearXNG (cf. URL ci-dessus), extrait les ids IMDb des résultats, valide via TMDB + juge de synopsis. Résout les titres québécois paraphrasés qu'aucun catalogue ne connaît (ex. « L'histoire de Jean Seberg » → film « Seberg » 2019). Inopérant si ni SearXNG ni clé Ollama ne sont configurés.
Si cochée, les orphelins marqués needs-review sont retraités (au lieu d'être sautés) — pour y repasser S3 une fois SearXNG configuré. En cas de résolution, le tag devient identified. Les déjà-identifiés restent sautés.

Audit santé du serveur

Lance un agent LLM qui interroge l'outil system_audit (sessions, tâches planifiées, transcodage, disques, journaux, métriques hôte) et produit un rapport Markdown de santé : constats tagués par gravité + actions recommandées. Réservé aux administrateurs. La remédiation (arrêter une session, déclencher une tâche, notifier un usager) est désactivée par défaut.
Option opt-in (décochée par défaut). Si cochée, le LLM peut exécuter des actions de remédiation pendant l'audit (arrêter une lecture, déclencher une tâche, envoyer un message). Tant que décochée, ces actions renvoient une erreur et le LLM se contente de les recommander dans le rapport. Le prompt d'audit demande de toute façon au LLM de ne jamais agir sans demande explicite.
single : l'LLM appelle lui-même l'outil system_audit de façon adaptative (peut creuser un journal suite à un constat). Convient à un modèle puissant (cloud). deterministic : le plugin rassemble lui-même toutes les sondes (zéro LLM) puis un seul passage LLM sans outils synthétise le rapport — conçu pour un modèle local/modeste (ex. gemma4), qui synthétise bien du texte fourni mais gère mal l'orchestration multi-outils. Note : la remédiation exécutable n'est possible qu'en mode single (avec le flag de remédiation activé) ; en mode déterministe elle reste rapport-only.
Orientation libre de l'audit (ex. un domaine à inspecter, ou une demande explicite de remédiation). Laisser vide pour un audit complet.

Chat avec l'assistant IA

Conversation interactive multi-tours avec l'agent LLM, sur sa propre page (menu Serveur → Chat LLM AI). Celui-ci dispose de tous les outils déjà disponibles (guide TV, bibliothèque, TMDB/TVDB, recherche web, Showbizz, audit système) et utilise les priorités de backends LLM configurées ci-dessus. L'historique est maintenu par la page ; la directive et la documentation des outils sont envoyées au LLM une seule fois, au début de la conversation. Réservé aux administrateurs.
